# 电商交易系统 · 接口自动化测试

> 一个接口自动化测试练手项目：用 pytest 给一个 Flask 电商后端写了一套可回归的接口测试框架。

## 项目简介
被测系统是用 Flask 写的电商后端（注册 / 登录 / 商品 / 购物车 / 订单 / 支付，共 16 个 JSON 接口）。
我围绕它设计了约 50 条测试用例（等价类 / 边界值 / 场景法），并搭建了一套基于 pytest 的接口自动化框架，
让这些用例可以一键回归，并由 GitHub Actions 在每次提交时自动运行。

## 我的角色（如实说明，面试就这么讲）
- **测试用例设计 + 手工执行 + 缺陷分析**：由我（乐大侠）完成。我先在 Apifox 里手工跑通全部接口，
  定位并记录了约 20 个缺陷（越权建商品、订单状态机缺失、支付金额校验缺失、浮点精度丢分等）。
- **pytest 自动化框架**：在我搭子（蛋蛋）的指导下搭建完成。我理解每一层的设计意图
  （接口封装 / 造数工具 / 测试夹具 / 数据驱动 / xfail 管理已知缺陷 / CI），
  并能讲清每条用例为什么这样设计。

## 技术栈
`pytest` · `requests` · `PyYAML`（数据驱动）· `Allure`（测试报告） · `GitHub Actions`（持续集成） · `Flask`（被测系统）

## 目录结构
```
.
├── app.py / seed_admin.py        # 被测系统（故意保留若干缺陷，作"靶子"）
├── tests/                        # 自动化框架
│   ├── api_client.py             # 第1层：接口封装（自动处理 token 关联）
│   ├── helpers.py                # 第2层：造数工具（随机用户名 / 注册 / 建商品）
│   ├── conftest.py               # 第3层：测试夹具（清库 + admin/user/api 三种客户端）
│   ├── test_*.py                 # 第4层：按模块组织的用例
│   └── data/register_cases.yaml  # 第5层：注册接口数据驱动
├── .github/workflows/test.yml    # CI：提交即起服务 + 跑测试 + 出报告
└── requirements.txt / pytest.ini / run_tests.cmd
```

## 怎么跑（本地）
1. 安装依赖：`pip install -r requirements.txt`
2. 初始化管理员账号：`python seed_admin.py`
3. 启动被测服务：`python app.py`（默认 5000 端口）
4. 运行测试：`python -m pytest -v --alluredir=reports/allure`
   （或直接双击 `run_tests.cmd` 一键：起服务 → 等健康检查 → 跑测试 → 关服务）

## 发现的缺陷（节选）
- **D3 越权**：普通用户也能建商品（应 403，实 200）
- **D14 状态机缺失**：未发货的订单可直接确认收货（应 400，实 200）
- **D10 浮点精度**：`1.005` 经 `round` 后入库变成 `1.0`，账上少 1 分
- 其余已知缺陷在测试用例中以 `xfail` 形式登记，由 CI 持续跟踪
